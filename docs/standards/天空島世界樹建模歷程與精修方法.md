# 天空島世界樹建模歷程與精修方法

> 專案：樹伴圈／生命樹浮島世界  
> 主要製作工具：Blender 5.2.1 LTS、Python 程序建模、Unity 6000.0.82f1  
> 歷程範圍：2026-09-01 至 2026-09-17；主樹精修重點至 2026-09-13  
> 文件目的：把這棵天空島世界樹從早期白模到後半段高完成度版本的做法，整理成可移植到其他遊戲專案的製作方法。

## 先說結論：這棵樹後來為什麼變得精細

後半段真正有效的改進，不是單純增加面數、貼圖解析度或葉片數，而是依照下列順序重做：

1. **先重畫整棵樹的受力與剪影**：七個主幹控制點形成連續 S 型重心，不再是直立圓柱上接幾根平均分叉。
2. **讓主枝有主次和方向性**：八條主枝不是鏡像排列；左右兩條長枝負責寬闊剪影，其餘枝條支撐前後深度和頂部高度。
3. **把葉冠從球團改成枝梢流**：葉子沿 11 股彎曲、旋展的枝梢路徑生長，而不是塞進球體、橢球或七塊均勻葉墊。
4. **先做中尺度，再做碎細節**：主幹扭轉、根頸膨脹、主根貼岩、次枝和末梢枝，全部比樹皮噪聲與單片葉紋更早處理。
5. **用尺度對照證明它是世界樹**：林地小樹縮小、島體加深、主枝拉長，觀者才會感受到巨大，而不是一棵普通園景樹被放大。
6. **材質服務形體，不掩蓋形體**：葉色依實際高度連續混色，樹皮以高粗糙度和低對比起伏表現；沒有用高亮塑膠感或高頻雜訊假裝精細。
7. **保留可維護的資料骨架**：16 個葉冠群組、8 根主枝、12 個紀念掛點和固定亂數種子保持穩定，外觀重做時沒有破壞遊戲資料接口。

一句話總結：**精細感來自大形、受力、層級、負空間、尺度與材質共同成立；面數只是最後承載這些判斷的工具。**

目前專案留存的是 Git、美術紀錄、程序建模腳本、Unity 實景與測試證據，沒有可逐字搜尋的完整聊天逐句紀錄。因此，無法用聊天原句精確標示「你說非常好」發生在哪一張畫面之後。

## 一、完整演進時間線

### 階段 0：先建立可運作的三維生命樹庭園

在正式浮島精修前，專案先完成 Unity 生命樹庭園的垂直切片、iOS／Android 原生串接與基本狀態控制。這一階段的價值是建立遊戲端資料與美術資產的接口，不是產出最終樹型。

一開始就保留幾個後來非常重要的結構：

- 成長階段資料；
- 主枝、葉冠和紀念物的穩定命名；
- 正常動態與降低動態模式；
- Blender 母稿、FBX／GLB、Unity 場景和統計檔之間的可重建流程。

這讓後續可以大幅修改外觀，而不用每次把遊戲資料、掛點和狀態邏輯全部推倒。

### 階段 1：2026-09-01，混合世界重製基礎

代表提交：`1e538b2`

第一輪重製把場景拆成「三維主樹與中央島＋二維原創遠景＋Unity 即時氣氛」。當時的目標是先把可動、可掛載、會反映遊戲狀態的內容留在三維場景，把遠景天空、雲海和遠島放在較省成本的背景板。

這一版做對了三件事：

- 主樹、中央島和紀念掛點保留為真三維；
- 遠景不冒充可互動世界，先控制手機成本；
- 保存原創概念圖、樹皮、葉簇、草地和岩層素材的來源與限制。

但畫面仍未通過美術門檻。主要問題是：

- 主樹缺少清楚的次枝與末梢枝；

- 雲和瀑布接近白模；
- 主幹與根部缺少重量；
- 增加同類幾何只會變重，不會自動變漂亮。

這是整段歷程最重要的早期認知：**可運作的程序模型，不等於具有美術判斷的模型。**

這一輪建立了樹皮、葉簇、草地與岩層材質，加入葉冠裁切著色器、三向投影材質、瀑布流光，以及可降低的待機動態。

當時的葉冠仍主要依賴三張交叉透明葉簇面片組成一個葉冠群，16 組葉冠共 48 張面片。優點是物件少、面數低、可以快速建立塊面；缺點則是：

這個版本的價值是完成可替換的材質和動態管線；它不是後來精細樹冠的最終答案。

代表提交：`ab264a7`

每個原本均勻的葉冠被拆成七組不等大的枝梢葉叢，並用面積權重分配葉片。主要葉叢較厚，周邊葉叢較小，不同葉冠以固定角度旋轉，避免像同一個印章重複蓋上去。

- 葉冠之間缺少連續的生長方向；
- 主枝沒有拉出足夠的橫向跨度；
- 遠看仍像園景樹，而不是遮天蔽日的世界樹。

這個失敗版本很值得保留，因為它揭示了從「球」改成「很多小球」仍不等於自然枝梢。

### 階段 9：2026-09-13，主幹、長枝與旋展葉冠重建

代表提交：`a2e0809`

這是本文最重要、也最適合移植到其他遊戲樹的後半段。

#### 9.1 主幹從偏折直柱改為連續 S 型受力

主幹使用七個控制位置：

```text
(0.00,  0.00, 0.05)
(0.42, -0.04, 0.78)
(0.72,  0.04, 1.45)
(0.54,  0.10, 2.10)
(-0.06, 0.02, 2.75)
(-0.45, 0.00, 3.35)
(-0.12, 0.02, 4.30)
```

半徑由根部到頂端依序收細：

```text
1.45 → 1.15 → 0.99 → 0.85 → 0.62 → 0.36 → 0.08
```

這組控制點不是可以直接複製到任何樹的萬用答案。真正可移植的是它的設計原則：

- 根部先向一側承重；
- 中段回拉，避免整棵樹倒向同一邊；
- 上段再次偏移，形成可辨識的節奏；
- 位移是連續曲線，不是折角；
- 粗細變化與受力一致。

曲線轉成網格後，又依主幹中心線加入低頻縱向起伏：五瓣主起伏加九瓣次起伏，根部振幅較大、往上減弱。這些起伏真的改變側影和擦邊光，不只是把高頻 noise 接到法線。

#### 9.2 八條主枝不再平均分配

八條主枝中，前三條負責主要剪影，其餘五條支撐厚度和上層冠幅。最外側左右主枝被拉到約 `x = -3.75` 與 `x = 3.80`，遠大於主幹本身的寬度。

設計邏輯是：

- 左右主枝長，但高度和前後位置不同；
- 後方枝提高，建立立體深度；
- 上層枝較短且收束，不跟下層搶同一條輪廓；
- 分枝起點分布在不同主幹高度；
- 主枝粗細有階級，前幾條明顯較粗。

每條主枝再生成兩條次枝，每條次枝再分出兩條末梢枝。也就是先建立清楚的三級結構：

```text
主幹
└─ 主枝
   ├─ 次枝
   │  ├─ 末梢枝
   │  └─ 末梢枝
   └─ 次枝
      ├─ 末梢枝
      └─ 末梢枝
```

細節之所以看起來成立，是因為觀者能從葉冠空隙看見枝條層級，而不是因為每根枝條都有大量表面紋理。

#### 9.3 葉冠從「葉墊」改為 11 股旋展枝梢流

這次把每個葉冠內原本七塊葉墊的分配方式完全拿掉，改成 11 股彎曲、旋展的 spray。每片葉子先選擇一股枝梢，再沿 `t = 0...1` 的生長進度決定距離、旋轉、起伏與少量散布。

概念化後的演算法如下：

```python
for each_canopy_anchor in 16_anchors:
    canopy_twist = anchor_index * 0.83 + front_back_offset

    for each_leaf in 1875_leaves:
        spray = leaf_index % 11
        t = deterministic_random_0_to_1()

        heading = spray * golden_angle + per_anchor_offset
        curl = heading + t * changing_curl_amount
        reach = lerp(near_center, outer_tip, t)

        center = curved_spray_position(
            heading=heading,
            curl=curl,
            reach=reach,
            vertical_wave=sin(t * pi + spray_phase),
            small_scatter=fibonacci_sphere_sample,
        )

        orient_leaf_upward_with_local_variation()
        write_height_based_vertex_colour()
```

這個方法比球體散布好的原因：

- 所有葉片都像是從枝梢方向長出來，不是均勻填滿體積；
- `reach` 隨 `t` 增加，自然形成中心厚、外圍疏的分布；
- 11 股枝梢有共同方向，但彼此相位不同；
- 每個葉冠再整體旋轉，16 組不會出現同一輪廓；
- 枝梢之間保留負空間，能露出主枝和天空。

最終每組葉冠 1,875 片葉子，16 組共 30,000 片。每片葉子由五個頂點、四個三角面構成，因此主葉群維持約 120,000 三角面。這裡的關鍵優化是：**葉子數增加，但單片從七頂點改成五頂點，讓總葉面成本不跟著失控。**

#### 9.4 葉片不是平面菱形，而是有主脈高度

五個葉片頂點中，四個形成輪廓，第五個是抬高的中心主脈。四個三角面由中心連向四邊，產生非常輕量的凹凸和受光變化。

這個做法比完全平面葉片多一個中心點，卻能在斜光和旋轉時保留體積。葉片長度約在 `0.032...0.060` 模型單位之間，寬度為長度的 `0.43...0.64`，避免每片葉子一樣大。

#### 9.5 葉色依真實高度連續混色

葉片使用五段綠色調色盤，但最終不是依葉片編號做硬切色帶，而是依葉片在枝梢內的實際高度算 exposure，再在相鄰色階間連續混色。

效果是：

- 上方與外圍葉片偏亮、偏暖；
- 內層與下方葉片偏深、偏冷；
- 不需要每片葉子獨立材質；
- 不會出現依生成順序形成的條紋。

頂點色 alpha 通道另存冠內環境遮蔽值，不拿來做半透明。葉材質維持不透明、低金屬、高粗糙，降低透明排序與 overdraw 問題。

#### 9.6 根系不是掛在島外，而是對岩壁取樣

六條主要垂根以 Blender `BVHTree` 對島體網格做射線相交。每條根在數個指定高度向岩壁投射，取得實際碰撞位置，再加入小幅方向偏轉：

```text
根頸 → 島面接觸 → 岩壁上段 → 岩壁中段 → 岩壁下段 → 收進岩壁
```

其中一條主根再分出兩條較細支根，但不新增另一圈同樣粗的帶狀根。這使根系有主次，而且末端真的消失到岩壁裡，不會像幾根尖刺懸空。

根部與主幹另經過：

- voxel remesh，體素尺寸約 `0.045`；
- smooth，係數 `0.75`、4 次；
- decimate，把固定主體控制在約 11,000 面的目標量級；
- 重新 UV 展開，保留 Unity 樹皮材質使用能力。

這些參數只適合當時場景單位。移植到別的專案時，應按樹高比例換算，不要照抄絕對數字。

#### 9.7 用林地小樹建立巨大尺度

主樹重做同時，林地小樹尺寸再縮小約 20%。這個改動沒有增加主樹任何細節，卻明顯提高世界樹尺度感。

做巨大物體時，畫面需要已知尺度的對照物：

- 小樹；
- 河道寬度；
- 瀑布；
- 台地層級；
- 雲層高度；
- 若有角色，角色只能作最小尺度參考。

如果所有東西一起放大，世界樹仍只會看起來像普通樹。

### 階段 10：2026-09-13，材質、岩壁、水幕與雲景整合

代表提交：`dc03430`

這一輪沒有再次重畫樹的骨架，主要是讓前一輪好看的形體在完整場景裡讀得出來：

- 葉色改為依局部高度連續混色；
- 枝梢散布半徑略收，減少毛躁；
- 葉片 alpha 儲存遮蔽值，但仍以不透明方式渲染；
- 岩壁增加低對比礦物色差，放棄過度規則的條紋候選；
- 瀑布保留連續藍色水體，只在局部加入白沫，不用細絲噪聲把整面水幕割碎；
- 遠雲改成較橫向的雲層，近雲縮小，讓樹冠和島體有清楚輪廓。

最終記錄的模型統計為：

- 99 個網格；
- 248,846 頂點；
- 218,316 三角面；
- 16 個葉冠群組；
- 12 個紀念掛點。

數字不是美術完成證明，但可以用來讓另一個專案預估同級資產的成本。

## 二、可移植到其他專案的完整製作流程

### Step 1：先定義樹在遊戲裡的角色

先回答：

- 它是背景、可近看的英雄資產，還是可攀爬場景？
- 相機能否 360 度環繞？
- 會不會成長、換季、掛紀念物或受傷？
- 目標是手機、桌機、主機還是離線渲染？
- 玩家最常看到的螢幕尺寸和距離是什麼？

天空島世界樹是英雄資產、可有限環繞、需要生長狀態和穩定掛點，因此不能只做一個合併後不可控制的漂亮模型。

### Step 2：用剪影圖設計大形，不先做樹皮

至少畫三張同尺度剪影：

- 正面；
- 左右 30～45 度；
- 俯視或後側。

只看純黑形狀，確認：

- 樹幹重心是否有辨識度；
- 左右冠幅是否不對稱但仍平衡；
- 主枝是否能被看見；
- 葉冠間是否有大小不同的負空間；
- 根部是否真的壓住地面或岩壁。

純黑剪影不成立時，先不要做樹皮節點、葉脈或粒子。

### Step 3：建立穩定資料接口

把需要被遊戲控制的節點先命名，例如：

```text
Tree_Root
Trunk_Main
Branch_Main_01 ... 08
Canopy_Back_01 ... 08
Canopy_Front_01 ... 08
Keepsake_Socket_01 ... 12
```

固定亂數種子，讓相同參數能重建相同資產。外觀迭代時，不任意重編掛點或把所有葉冠合成一個無法控制的網格。

### Step 4：只用 6～9 個控制點畫主幹

英雄樹的主幹先追求清楚、可調的低頻曲線，不需要一開始就有很多節點。

檢查原則：

- 相鄰三點形成連續受力，不做九十度折角；
- 根部最粗，分枝後逐段收細；
- 粗細變化不要等速，分枝和受力位置可以局部膨脹；
- 至少一段回拉中心，避免整棵樹像被風吹倒；
- 最上段不要又回到完全垂直的預設樹形。

### Step 5：先放 3 條剪影主枝，再補到 6～10 條

不要一開始平均生成十幾條枝。先讓三條枝決定：

- 最大左右跨度；
- 最高點；
- 前後深度。

確認剪影後，再加入支撐枝。每條枝都要回答「它負責哪一塊畫面」，不能只是填空。

### Step 6：建立主枝、次枝、末梢枝的粗細階級

可使用曲線 bevel 或骨架蒙皮，但必須分三級。實務上可從相對半徑開始：

```text
主枝起點半徑：1.00
主枝末端半徑：0.08～0.15
次枝起點半徑：0.35～0.55
次枝末端半徑：0.03～0.08
末梢枝起點半徑：0.15～0.30
末梢枝末端半徑：0.01～0.04
```

這是比例概念，不是固定模型單位。

### Step 7：先做葉冠質量塊，再做單片葉子

用簡單低模量塊檢查 16 個左右的葉冠錨點：

- 前後至少分兩層；
- 大小和高度不相同；
- 不沿左右鏡像；
- 不形成整齊階梯；
- 主枝末端附近較厚，枝間保留空洞；
- 旋轉 35 度後仍成立。

量塊通過後，才把每塊替換成枝梢流葉片。

### Step 8：沿枝梢曲線散布，不在球體內均勻撒點

每個葉冠先建立 7～13 股枝梢流。每股具有：

- 起始方向；
- 彎曲量；
- 長度；
- 上拱或下垂；
- 末端疏化；
- 少量局部亂度。

葉片位置由「枝梢參數 `t`＋小幅散布」組成。不要只用隨機球體位置，否則再多葉片都只是球。

### Step 9：選擇適合平台的葉片表示法

可用下表決策：

| 方法 | 優點 | 缺點 | 適合情境 |
| --- | --- | --- | --- |
| 交叉葉簇卡片 | 面數低、製作快 | 透明 overdraw、環繞易穿幫 | 遠景樹、固定相機 |
| 五頂點立體葉 | 斜光有體積、可不透明 | 幾何量增加 | 英雄樹、有限環繞 |
| 完整高模葉 | 近拍最好 | 成本高、LOD 複雜 | 桌機／主機近距離 |
| 幾何節點實例 | 母稿可調、散布彈性高 | 匯出前需實例化與整併 | Blender 主導的可重建管線 |

天空島世界樹選五頂點立體葉，是因為它需要環繞體積，但仍要控制到遊戲資產成本。

### Step 10：讓根系與地形共同生成

不要先完成一棵獨立樹，再把它擺上島。

建議流程：

1. 先確定島面與岩壁大形；
2. 建立 BVH／碰撞查詢；
3. 從根頸往預定方向發射射線；
4. 取得地形表面點；
5. 在接觸點外推少量距離，避免完全埋入；
6. 末端向內偏移，讓根消失進岩壁；
7. 只挑一兩條根分出細支根；
8. 檢查根部遮蔽、重量和輪廓。

### Step 11：用頂點色做大範圍光色，不為每片葉子建材質

把局部高度、朝向、枝梢內外位置或 AO 寫入頂點色。Unity 端用一個共用葉材質讀取：

- RGB：深綠到暖黃綠的連續色階；
- A：環境遮蔽或其他非透明資料。

這樣能維持少量材質和 draw call，也方便季節色統一調整。

### Step 12：每個可動葉冠整併為一個網格

保留 16 個葉冠錨點，但每個錨點下的葉片在匯出前合併成一個網格。不要匯出 30,000 個葉片物件。

這棵樹採用的折衷是：

- 遊戲仍可分別驅動 16 組葉冠；
- 每組內葉片合併；
- 樹枝、主體與紀念掛點仍分開；
- 資料接口和渲染成本同時可控。

### Step 13：最後才做樹皮和微細節

樹皮的程序材質應保持中低頻：

- 高粗糙度；
- 低金屬度；
- 低對比色差；
- 沿樹幹方向拉長的紋理；
- 受控 bump，不把輪廓變成噪聲毛邊。

如果需要更高品質，先雕刻樹瘤、樹洞、斷枝、根頸膨脹和局部剝落，再烘焙到遊戲低模。不要以均勻高頻 noise 代替中尺度雕刻。

### Step 14：用尺度參照完成「巨大感」

至少放入三種尺度：

- 主樹；
- 林地小樹／岩塊／道路；
- 更小的角色、設施或可辨識物。

同時使用空氣透視、遠近雲層和較小遠景對照。世界樹本身不需要無限放大，對照物縮小往往更有效。

### Step 15：固定相機與光線做前後比較

每次改版都輸出：

- 正面；
- 左 35 度；
- 右 35 度；
- 橫幅／遠景；
- 無材質剪影；
- 根部近照；
- 同一時間點的動態畫面。

只有近拍變細緻、但縮回遊戲主畫面看不出差異，就不算真正改善。

## 三、最容易讓樹看起來不夠精細的錯誤

### 1. 先加葉子，後改剪影

錯誤結果：面數提高，仍是一棵普通圓冠樹。

正確順序：主幹重心 → 主枝跨度 → 葉冠量塊 → 枝梢流 → 單片葉子。

### 2. 把均勻球冠拆成很多小球

錯誤結果：從一個球變成葡萄串或盆景葉墊。

正確做法：以有起點、方向、彎曲和末端的枝梢流組織葉片。

### 3. 左右枝條鏡像

錯誤結果：像圖示、人工裝飾樹或遊戲預設資產。

正確做法：一側承擔主要剪影，另一側保留負空間；高度、長度、前後位置和粗細都不完全對稱。

### 4. 所有枝根粗細接近

錯誤結果：沒有重量與受力，像管線組合。

正確做法：建立主幹、主枝、次枝、末梢枝，以及主根、次根、細根的清楚階級。

### 5. 根只是擺在地面上

錯誤結果：樹像完整模型放在圓盤上，沒有長在島裡。

正確做法：讓根與地形共構，以射線取樣、遮蔽、局部融合和末端埋入建立重量。

### 6. 以高亮和高對比假裝細節

錯誤結果：塑膠、廉價金屬或過度遊戲化。

正確做法：先用形體與遮蔽建立深度，材質保持高粗糙度、受控對比和少量色溫變化。

### 7. 無控制亂數

錯誤結果：每次重跑都變成不同樹，無法比較版本、修正穿插或保留掛點。

正確做法：固定全域種子，再依葉冠索引派生局部種子。

### 8. 只看正面

錯誤結果：側面像紙片、葉冠露出卡片交叉、根部懸空。

正確做法：至少固定正面、左右 35 度與根部近照，環繞功能存在時再做連續動畫。

### 9. 把測試通過當成美術通過

幾何測試可以證明：掛點存在、溪流貼地、資產可匯出、降低動態有效。它不能證明樹好看。

美術仍需要：

- 同相機前後圖；
- 剪影審查；
- 多角度目視；
- 遊戲實際尺寸；
- 真機效能；
- 主要負責人的畫面確認。

## 四、建議直接套用的製作檢查表

### 大形

- [ ] 關閉材質後，樹仍有可辨識的重心與剪影。
- [ ] 主幹不是直柱，也沒有硬折角。
- [ ] 至少三條主枝分別負責左右跨度、最高點與前後厚度。
- [ ] 左右不鏡像，葉冠有大小不同的負空間。
- [ ] 縮到實際遊戲畫面尺寸仍能看出主枝。

### 枝幹

- [ ] 主幹、主枝、次枝、末梢枝粗細階級清楚。
- [ ] 分叉處沒有平均鼓包或明顯夾縮。
- [ ] 末梢枝真的進入葉冠，不停在葉冠外面。
- [ ] 至少有少量斷枝、樹瘤或局部膨脹，但不均勻鋪滿。

### 葉冠

- [ ] 葉子沿枝梢流分布，不是球體亂撒。
- [ ] 前後葉冠分層，旋轉後仍有厚度。
- [ ] 主要葉叢厚、外圍疏，邊緣不形成規則圓球。
- [ ] 葉色依高度、朝向或遮蔽連續變化，沒有硬色帶。
- [ ] 葉片表示法符合目標平台與相機距離。

### 根與地形

- [ ] 主根壓入或繞過地表，不是浮在上面。
- [ ] 垂根沿實際岩壁取樣，末端收進岩壁。
- [ ] 主根、次根和細根有明顯主次。
- [ ] 根部接觸處有陰影、遮蔽和重量。

### 材質

- [ ] 樹皮高粗糙、低金屬，色差不過度。
- [ ] 中尺度樹瘤與裂損先於高頻 noise。
- [ ] 葉片不靠高金屬度或強鏡面製造亮點。
- [ ] 瀑布、雲與岩壁不搶走主樹輪廓。

### 遊戲資產

- [ ] 亂數種子固定，可重建同一棵樹。
- [ ] 掛點名稱和索引穩定。
- [ ] 葉片以群組整併，不輸出成大量獨立物件。
- [ ] FBX／GLB、母稿、統計與引擎場景同步更新。
- [ ] 實際裝置量測幀率、記憶體、透明成本與發熱。

### 證據

- [ ] 同相機、同光線、同成長階段的前後圖。
- [ ] 正面、左右 35 度、剪影與根部近照。
- [ ] 旋轉或風動來自引擎實際畫面，不以概念動畫冒充。
- [ ] 測試通過、美術通過、真機通過分開記錄。

## 七、給下一棵樹的最短實作配方

如果要在另一個遊戲專案重做同級效果，最短但不失真的順序是：

1. 畫三視角黑色剪影，先決定 S 型主幹和三條主剪影枝。
2. 擴成 6～10 條不對稱主枝，補次枝與末梢枝。
3. 建立前後兩層、約 12～20 個不同尺度葉冠錨點。
4. 每個錨點建立 7～13 股枝梢流，葉片沿曲線參數分布。
5. 使用五頂點立體葉或適合平台的替代表示法，寫入高度色與 AO。
6. 每個葉冠整併成一個網格，保留群組控制，不保留單片物件。
7. 根據實際地形做射線貼合，讓主根壓入地面、垂根收進岩壁。
8. 用小樹、道路或角色建立尺度對照。
9. 加入高粗糙樹皮、低對比礦物岩層與不搶剪影的雲水材質。
10. 固定相機輸出正面、左右 35 度、剪影、根部與實際遊戲尺寸，再決定是否增加細節。

只要前四步沒有完成，先不要花時間雕每片葉子或製作 4K 樹皮。這正是早期版本和後半段高完成度版本之間最大的差別。
