# 《承天》畫質分級與模型交件 v1

> 2026-11-02，Claude Code 依 z1nnz 指示撰寫：「可以分件，有一段是網頁或電腦端，有一邊的建模手機端有些跑不出來，或要到一定幀數才能出來，就像原神有安裝包、幀率、畫質。」
> 接在[遊戲製作總綱](../game-production-bible.md)第 15 節的效能預算之後。**這裡的數字是目標，手機還沒有實測過**（K9 待做），實測後再調。

## 一、原則

**同一份模型，畫質越高看到越多。** 我們不為手機做另一批模型，也不為了手機把好模型改差（[品質優先](../art/modeling-style-spec-v1.md)第 6 節）。手機和網頁靠 LOD、貼圖縮小、分段下載、關掉部分細節來跑得動。

## 二、三個畫質檔

| | 標準 | 高 | 極高 |
|---|---|---|---|
| 給誰 | 手機瀏覽器、手機 App、舊電腦 | 電腦瀏覽器、新手機 | 電腦安裝版 |
| 幀數目標 | 30 fps | 30–60 fps | 60 fps |
| 單一畫面三角面（上限） | 30 萬 | 80 萬 | 150 萬 |
| 貼圖記憶體（上限） | 300 MB | 800 MB | 1.5 GB |
| 近處的模型 | LOD1 為主，10 m 內才換 LOD0 | LOD0 | LOD0，切換距離拉長 |
| 貼圖 | 引擎縮到最大 1024 | 引擎縮到最大 2048 | 原尺寸 |
| 地被、灌木密度 | 40% | 70% | 100% |
| 「高畫質細節」（第四節） | 不出現 | 部分 | 全部 |
| 陰影、水、霧 | 簡化 | 中 | 完整 |

玩家可以在設定選自動／標準／高／極高（K15）；自動模式已有基礎（K9：低於 40 fps 自動降解析度和陰影距離，高於 57 fps 調回）。

## 三、下載和安裝包

| 平台 | 第一次下載 | 之後 |
|---|---|---|
| 網頁（現在的主力，給人馬上玩、測試） | 第一段 ≤ 15 MB 目標（K6），只有標準檔 | 走到哪個區塊下載哪個 |
| 電腦安裝版 | 基本包；另一個可選的**高畫質資源包** | 不想要的人可以不裝 |
| 手機 App（之後） | 基本包＋區塊資源包 | 可選下載 |

資源包怎麼拆（Unity Addressables）由核心組做。

## 四、做模型的人要怎麼交

一份母檔就好，多做的只有下面四件事，**不用為每個平台各做一次**：

1. **LOD0 不減**，照品質做；LOD1 約 50%、LOD2 約 15%，同一檔案。LOD1 是**手機近處會看到的版本**，所以 LOD1 的輪廓和主要結構也要好看，不能只是自動減面的破面。
2. **細節分開**：可以拿掉也不影響看懂的小東西（藤蔓、掛繩、零碎雜物、小石子、落葉）做成子物件，命名 `Detail_*`。標準檔會關掉它們。
3. **貼圖照上限做一套**（一般 2048 以內）。縮小由引擎處理，不用另外做低解析度版本；但縮到一半時大塊顏色和形狀要還看得懂。材質用一般的 PBR 貼圖組，特殊效果（發光、濕、溫）用參數，且參數為 0 時要正常好看。
4. **`model_info.json` 加兩個欄位**：

```json
{ "minTier": "standard", "detailObjects": ["Detail_Vine", "Detail_Rope"] }
```

`minTier` 的值：

| 值 | 用在 | 例子 |
|---|---|---|
| `standard` | 主要建築、地標、要互動或擋路的東西，**所有人都看得到** | 水磨坊、石橋、飛升榜 |
| `high` | 增加豐富度的擺設 | 大量灌木變體、路邊小物 |
| `ultra` | 只為了更美的細節 | 額外落葉層、水邊細碎花草 |

**重要的東西一定是 `standard`**：玩法要用的、故事要看到的、會擋人的，不可以標成 `high` 或 `ultra`，否則手機玩家看不到或穿牆。碰撞不分檔。

審圖多交一張：同一個角度，LOD0 和 LOD1 並排，並關掉 `Detail_*`。
