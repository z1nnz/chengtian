# 區塊製作流程 v2：先有多角度設定圖和物件清單，再設計、建模、整合

- 日期：2026-11-14
- 依據：z1nnz 指示。重點三句：
  1. 「每個場景需要多個角度的圖片，讓 Codex 可以更好地規劃各個物件要怎麼擺。」
  2. 「它所產生的圖，讓你可以判斷我們要製作多少物件。一個區塊裡需要非常非常多物件。」
  3. 「我只叫你達到他（Josh）的水平，而不是叫你學他的建模技術。」
- 這份取代 `codex-v8-world-planning.md` 和 `codex-v9-design-and-integrate.md` 裡的流程；兩份裡的工具說明（建置、截圖、匯入器寫法）照舊有效。

## 一、為什麼要改

| 問題 | 實際數字 |
|---|---|
| 每塊只有一張主視覺，有的還沒有 | KA01–KA13 共 13 張對 13 塊；Codex 的工作區裡 KA11（D2）還缺 |
| 設計太薄 | Codex v8 用約 30 分鐘交了 6 塊設計，平均一塊 4–5 分鐘 |
| 物件太少 | 100 × 100 m 的一塊：D2 只擺 17 件、D6 27 件、A5 30 件、D4 32 件（A1 村子也才 62 件、39 種）。其餘靠自動種樹種草補 |
| 沒有一塊走完全程 | 5 塊有場景、6 塊有設計資料，但沒有任何一塊通過「氣氛」和「對圖」 |
| 缺件清單是猜的 | 施工圖粗估只缺二十幾種模型；沒有從畫面逐件數過 |

## 二、分工

| 誰 | 做什麼 |
|---|---|
| Claude Code | 每塊的**設定圖組**（Chrome 的 ChatGPT 生圖、下載原圖）、**物件清單**（看設定圖組逐件數）、**建模**（ChatGPT 三視圖 → Blender）、審查 |
| Codex | 依設定圖組和物件清單做**佈局**（地形、路、平台、每件物件座標），再**整合進遊戲**（匯入、建置、同鏡位截圖、對圖修改） |
| 協作者 Josh、Eli、John | 模型包（清單裡量大、成套的東西） |

建模方法不限：可以用 Josh 的零件函式，也可以自己寫、雕刻、圖轉 3D。**只看成果**：和 Josh／Eli 的同類作品並排，看起來不輸才收。

## 三、每一塊的六步

### 步驟 1　設定圖組（Claude Code 用 Chrome 的 ChatGPT 出，每塊 6 張）

11/14 z1nnz 再次指定：場景規劃圖由 Claude Code 在 Chrome 的 ChatGPT 生圖（沒有額度問題），**原圖直接下載**不用截圖；出完由 Claude Code 比對是否符合對這一塊的規劃，不符合就重出。同一塊的六張在同一個對話裡出，先出 V1 俯視圖，後面五張都寫明「同一個地方、同樣的配置」。D2 的六張已由 Codex 出好，照用。

| 編號 | 圖 | 用途 |
|---|---|---|
| V1 | **俯視 45° 全區**（整塊 100 × 100 m，標得出入口、路、地標、水） | 佈局的主要依據 |
| V2 | **入口第一眼**（玩家從上一塊走進來，眼高 1.6 m） | 第一印象、視線引導 |
| V3 | **主地標近景**（走到地標前 10–15 m） | 地標本體和周圍小物 |
| V4 | **反向回看**（站在地標旁往入口看） | 確認背面不是空的 |
| V5 | **通往下一塊的出口**（看得到下一塊的地標或地勢） | 區塊之間的銜接 |
| V6 | **地面與小物近景**（3 m 內：地面材質、草、石、落葉、小道具） | 前景密度、地面貼圖、小物種類 |

存 `art/references/blocks/<ID>/V1.png`…`V6.png`（**原尺寸下載**，不用截圖）、`prompt.txt`。既有的 KA 主視覺當 V2 或 V3 用，不重畫。

### 步驟 2　物件清單（Claude Code）

看著 6 張圖，把畫面裡**每一種東西**列出來，寫成 `docs/execution/world-plan/<ID>-inventory.md`：

| 欄位 | 內容 |
|---|---|
| 物件 | 名稱、大約尺寸、出現在哪幾張圖 |
| 層級 | 地標／建築與大型／中型道具／小物／植被／地面與貼花／特效 |
| 數量 | 整塊大約幾件（照 V1 數） |
| 來源 | 已有（寫模型路徑）／要改色或改版／**缺** |
| 誰做 | Claude Code／Josh／Eli／John／Codex（卡片、貼圖） |

**每塊的最低密度（不含草）**：

| 層級 | 種類 | 件數 |
|---|---:|---:|
| 地標 | 1–3 | 1–3 |
| 建築與大型（屋、橋、巨石、巨根、崖） | 5–10 | 10–30 |
| 中型道具（籬、柴堆、車、石燈、木樁、倒木…） | 15–25 | 80–200 |
| 小物（罐、籃、工具、碎石、蕈、花叢…） | 20–30 | 150–400 |
| 樹與灌木 | 8–12 | 100–300 |
| **合計** | **約 50–80 種** | **約 350–900 件** |

村子、街道類的區塊取上限；深林類建築少，但樹、根、石、倒木、蕨的種類要補足。

### 步驟 3　佈局（Codex）

輸入：6 張圖、物件清單、相鄰區塊的 JSON。輸出照 v8 第 4 節（`<ID>.md`、`<ID>-plan.png`、`blocks/<ID>.json`），加三條：

1. 清單裡每一種物件都要出現在佈局裡，件數接近清單；缺的模型也照樣給座標（`status: "missing"`）。
2. 小物不要一件一件手擺：用「聚落」寫法（中心點、半徑、種類和件數、朝向規則），由程式展開。每個建築、每段路邊、每個停留點周圍都要有聚落。
3. 6 張圖的相機位置各算出一組世界座標（位置、朝向、時間），寫進 `shots`，之後用來同鏡位對圖。

### 步驟 4　建模（Claude Code＋協作者）

清單裡「缺」的東西：成套、量大的寫成工作包寄協作者；零散、要對圖的由 Claude Code 做。每件：ChatGPT 三視圖（原圖下載）→ Blender → 預覽 → 和協作者同類作品並排 → 不如就重做 → 開 PR。

### 步驟 5　整合（Codex）

照 `codex-v9-design-and-integrate.md` 第 3 節：匯入器 → 登記 → 建置和自動測試 → 用 6 個鏡位截圖 → 和 6 張設定圖並排 → 改到像（至少兩輪）→ 走一遍 → `<ID>-built.md`。

### 步驟 6　驗收（Claude Code 審，z1nnz 看）

六項檢查（地形、模型、植被、氣氛、對圖、測試）＋密度達到步驟 2 的最低數字。六張並排圖給 z1nnz 看過才算這一塊完成。

## 四、順序

**先把一塊做到完，再做下一塊。** 不再一次設計很多塊。

| 順序 | 區塊 | 說明 |
|---:|---|---|
| 1 | **D2 古樹神木** | 試做塊：建築少，先把流程跑通。Codex 已有的 D2 設計當草稿 |
| 2 | **A1 青溪村** | 玩家待最久的地方，用新流程補到上限密度 |
| 3–5 | A2、A3、A4 | 已有場景，補設定圖組、清單、密度 |
| 6–13 | D3、D1、A6、A5、D4、D6、B1、B2 | Codex v8 的六份設計當草稿，照新流程重做 |

工作量估計：13 塊 × 6 張 = 78 張設定圖；每塊新增模型以 20–40 種估，第一圈合計約 300–500 種（含協作者已交的 360 多件裡可重用的）。確切數字每塊清單出來後更新在這張表下面。
