## 5. 合併

**合併前一定要 z1nnz 明確同意。** 報告時分清楚你驗過什麼、沒驗過什麼：z1nnz 曾經直接問「所以你都確定東西都看過是可以的嗎」，當時 Unity 編譯和模型外觀都還沒驗。不要讓「CI 綠燈」聽起來像「看過了」。

**實際步驟（2026-11-02 合併 #54–#63 的經驗）**

1. `main` 有 ruleset，不能直接推。一律走 PR，**squash merge**，作者署名保留給協作者。
2. 由舊到新一個一個合。每合一個，其他 PR 就落後 main，要先 update-branch。
3. update-branch 之後，**等 GitHub 回報 `mergeable_state: clean` 才合併**。同一個檢查會跑兩輪，只看第一輪通過會被擋（`Required status check ... is in progress`）。合併時帶上 `sha`。
4. 每個 PR 約 2–4 分鐘 CI，整批放背景跑，不要輪詢到卡住。
5. `.gitignore` 衝突：兩邊都留。[#65](https://github.com/z1nnz/yun-jing-rpg/pull/65) 就是在解決這件事，還沒合併。
6. **分支在協作者 fork 上的 PR**：我們推不了含 LFS 的合併結果（`You need Push access to upload Git LFS objects`）。請作者自己合 main，或由 z1nnz 在網頁按 Resolve conflicts。
7. 不動別人的分支、不強推、不關規則、不刪測試。
8. 合併後把 main 合回 `feature/qingxi-creek-chapter`，並更新總帳（例如總帳裡 #60 還寫「審查中」，實際已合併）。
