## 2. 新規則（這次開始，優先於 v3）

1. **每件有時間上限**：規格時數 × 1.5。到了就把最好的一版交成「候選」，寫清楚哪裡不滿意，做下一件。
2. **每個階段最多修 2 輪**（原本 3 輪）；每件最多到 v004。
3. **做完一件就提交並推上去**，不要堆。作者一律 `z1nnz <202040543+z1nnz@users.noreply.github.com>`，不加 AI 署名。
4. **照標註規則** [`docs/standards/labeling-v1.md`](../../standards/labeling-v1.md)：
   - 分支 `art/codex-1108-<主題>`（程式用 `game/codex-1108-<主題>`），從 **`origin/main`** 開，不要從 creek-chapter 開。
   - 提交訊息用 ID 開頭，例如 `RI01: 修 LOD0 近共面`。
   - 每個素材資料夾的 README 開頭照第 5 節的表。
   - PR 由 Claude Code 開。你推完後在回報寫「分支名稱＋包含的 ID」。
5. **只提交最後一版**：失敗的中間版本留在本機，不進 Git，只在 README 寫一行「v001–v003 為什麼不行」。
6. **生圖做不好就換方法**：透明遠景改成不透明長條＋上緣漸層；大山體改用高度圖置換或雕刻，不要一直重抽圖。
7. **每做完 10 小時**，在 `PRODUCTION_STATUS.md` 最上面加一行進度（日期、做完幾件、卡在哪）。
8. 原本的規則照舊：不做人物、不寫字、不重複別人在做的、品質優先、誠實寫 FAIL。

工作樹放 `D:\chengtian\1-進行中\codex-v4-<主題>`。主專案目前還在 `D:\yun-jing-rpg`（之後會搬到 `D:\chengtian\chengtian`）。只放新檔的美術分支可以用 `GIT_LFS_SKIP_SMUDGE=1` 開，比較快；D 部分要開 Unity，要完整下載 LFS。
