> 這一輪三份包都是**純建模**，沒有玩法、沒有角色。順序：手上 11/14 的包照常先做，做完再接這一份（未完成的舊包沿用，不重算時數）。

## 一、為什麼標準又提高了

11/15 z1nnz 把 D2 古樹神木的遊戲畫面和設定圖並排看，判定只有約 40% 像，並定下新的驗收線：

1. **整塊場景要和設定圖 85–90% 像才算過關。** 單件模型也一樣：擺進場景、用設定圖同一個鏡位截圖，放在一起要看不出是兩種東西。
2. **樹、樹根、木頭的樹皮一律要用「真實掃描樹皮」的做法**（第三節）。光滑圓管加畫上去的條紋，一律不收，包括核心組自己做的。
3. **所有樹都要做到和天空島世界樹差不多**（`docs/execution/2026-11-14/tree-method/`）。

石頭、石階、石台這一類，核心組的 AL01 祭壇台石和 SS01 半埋踏石已達標，可以當並排比較的範本。

## 二、每件都要交的東西

| 項目 | 規定 |
|---|---|
| 參考圖 | 先有圖再建。區塊的六張設定圖在 `art/references/blocks/<區塊>/`；單件的三視圖或細節圖可以**請 Claude Code 在 ChatGPT 出**（在 PR 或信裡寫要哪一件、要什麼角度） |
| 對圖 | 每件交一張「成品渲染 vs 設定圖裡同一個東西」並排圖，同光、同角度。不像就改到像 |
| 形狀 | 中低頻的起伏（石頭的稜、木頭的裂、磨損的邊）做在幾何上，不靠貼圖畫 |
| 貼圖 | 一般件 1024；比人大的件（建築、大石、大根、大樹）2048。Albedo／Normal／ORM／MaskURP |
| LOD | LOD0 不刪細節；LOD1 約 50%；LOD2 約 15%；照 `docs/standards/quality-tiers-v1.md` 用 `Detail_*` 子物件和 `minTier` |
| 碰撞 | 走得到、會擋路的件要有碰撞殼 |
| 比例 | 預覽圖裡放 1.75 m 人形尺 |
| 文件 | `model_info.json`、README（實際工時、用了哪些外部素材和授權） |
| 風格 | 中國南方山村與山林，**不要日式**；所有文字位置一律空白 |

## 三、樹皮標準（樹、樹根、倒木、木樁、木板舊木都適用）

1. **用實物掃描的樹皮材質**當底：Poly Haven（CC0，可商用、免註明）。核心組選定、已在用的三組：
   - `bark_brown_02`（灰褐老樹皮，D2 神木用這組）https://polyhaven.com/a/bark_brown_02
   - `jolcham_oak_bark_01`（長苔的橡樹皮）https://polyhaven.com/a/jolcham_oak_bark_01
   - `pine_bark`（松樹皮）https://polyhaven.com/a/pine_bark
   其他樹種可以自己在 Poly Haven 找，README 寫清楚用哪一組。
2. **凹凸要做成形狀**：高模用掃描的 Displacement 圖把樹皮板和裂溝真的推出來（裂溝深 5–15 cm，看物件大小），再烘焙到遊戲用的低模 Normal 圖。只貼 Normal 不推幾何的，側光一照就是平的，不收。
3. **大形狀先於細節**：樹根、樹幹要有順著纖維扭轉的粗稜、根頸張開、分岔、尾端鑽進土裡，不能是粗細一樣的圓管。
4. **顏色**：深灰褐，凸起處偏灰白；凸起處有少量灰白地衣斑；裂溝更暗。**不要淺土黃、不要整根一個顏色。**
5. **苔**：一塊一塊長在朝上的面和裂溝裡，要有厚度（幾何或至少 Normal 有毛絨感），不是噴一層綠。

核心組的樣品與程式：`D:\chengtian\4-素材與快取\bark-sample\`（`godtree_base.py`、`bark_sample.py`），推上 GitHub 後會在這裡補路徑。
